## Findings

| **CHEN-01** | **CRITICAL** | **"Fail closed" is inverted with respect to trust.** The plan's safety story for an unclassifiable delegation is *"answered as a question — today's behaviour — and **never** treated as a write."* But "answered as a question" is not a no-op and not low-authority: it admits a **user-attributed, turn-starting** prompt. So the fallback for the very content that could not be classified is written into the session under the **highest-authority provenance (`kind:'user'`)** and **wakes a turn**. The plan presents this as the safe default; from a trust standpoint it is the least-safe one — strictly worse than either verb, both of which are at least attributed to the voice. | `docs/sprint-plan-voice-presence.md:89-91` (fail-closed text); `packages/realtime-responder/src/index.ts:483-488` (admit → `controller.prompt({…mode:'queue'})`); `~/dev/deepseek-harness/packages/api/session-controller/src/commands.ts:331` (`const source = { kind: 'user', rpcId: … }`); `packages/realtime-responder/src/turn.ts:298-409` (the runner admits and starts a turn). | Redefine fail-closed by **effect, not classification**: an unclassifiable delegation must (a) be answered **out loud only** with **no session write**, or (b) be written with the **voice** source, never `user`. Add a fixture asserting that the ambiguous delegation produces **no `user/message`** in the session log. State in P1 that "answer" implies a write and which provenance it carries. |
| **CHEN-02** | **CRITICAL** | **A new write privilege is granted with no consent/approval story, and the plan never treats it as one.** `say` = `agent.followup()` → **starts a turn** in a tool-bearing coding session; `note` = `agent.inject()` → **seeds model-facing context** into that same session. The plan never uses the words *privilege, consent, permission, approval*, and never names the harness's own tool-approval gate as the backstop on the turn a `say` starts. Nothing bounds what the voice can talk a session into. The research the plan cites demands the opposite: *"once an LLM agent has ingested untrusted input, it must be constrained so that it is impossible for that input to trigger any consequential actions"* and OWASP *"Require explicit confirmation for side effects, bound to the exact action… Fail closed for unknown tools or missing approval requirements."* The plan applies the OWASP rule **only to the note** ("a note that fails validation is dropped") and **omits it entirely for the `say`** — the verb that actually has side effects. | `docs/sprint-plan-voice-presence.md:167-169` (`say` writes + starts a turn), `:190-222` (P3 applies OWASP fail-closed to the note only), `:266-276` (invariant table — no privilege row); `research/session-messaging-protocols.md:268` (§5.3), `:283` (§5.5 rule 2). Repo grep for `approval|consent|permission|privilege` finds no plan content (`docs/`, `packages/*/src/`). | Add an explicit **privilege section**: name the write as a capability grant; state that the resulting turn is a normal DSH turn and that **the session's tool-approval gate is the backstop**; add a fixture proving a `say`-started turn cannot bypass that gate. Scope the grant (which session(s), which forms). This is the single biggest omission in the plan. |
| **CHEN-03** | **HIGH** | **The plan's provenance premise is factually wrong against the code — and the proposed `kind:'realtime'` is unsafe.** Three parts: **(a)** *"no runtime validation… a new source `kind` is a pure type-level addition"* is **false**: the V2→V3 session-format migration enumerates kinds and **throws** on any it does not know — a session containing a `kind:'realtime'` message becomes **un-migratable**. **(b)** The cited precedent is wrong: `dsh-schedule` writes `{ kind:'plugin', plugin:'schedule' }`, **not** `kind:'schedule'`; there is no `schedule` kind anywhere, and `MessageSourceMap` lists only `user/plugin/model/tool` — so `session-messaging.md` §3's *"MessageSourceMap already reserves `schedule: { kind:'schedule' }`"* is false. **(c)** The plan contradicts itself: P2 story 1 proposes `kind:'realtime'`, P2 story 3 says *"the exact shape `dsh-schedule` uses."* | `~/dev/deepseek-harness/packages/session/session-format-v2-to-v3/src/payload.ts:10` (`SOURCE_KINDS` set), `:112-114` (`assertSource` → `throw new SessionFormatUnsupportedMigrationError('cannot safely transform unclassified message source')`); `packages/schedule/schedule/src/runtime.ts:269-273` (`{ kind:'plugin', plugin:'schedule' }`); `packages/llm/llm/src/message.ts:102-107` (`MessageSourceMap`); grep for `kind: 'schedule'` across the harness returns **nothing**; `docs/session-messaging.md:191-193` (the false claim); `docs/sprint-plan-voice-presence.md:159-161` vs `:167-169`. | Match the shipped precedent: `{ kind:'plugin', plugin:'realtime' }` — already in `SOURCE_KINDS`, already rendered by the projection, **no harness change**. If a distinct kind is genuinely wanted, add it to `SOURCE_KINDS` in the harness **first** and gate P2 on that. Correct `session-messaging.md` §3 and the plan's traceability so the premise is not carried forward. |
| **CHEN-04** | **HIGH** | **Model-authored text is delivered into the session as the *user* — on the dominant path, which the plan does not touch.** The question path forwards the **whole** transcript, including the model's own **`output` speech**, through `controller.prompt()`, which hard-codes `source:{kind:'user'}`. So the voice assistant's own words land in the session log as a `user/message`. The plan's P2 story 2 claim — *"attribution is stamped in the transport, never taken from the model; no model-supplied field may name it"* — is **true only of the two new verbs**; the path that runs on **every** delegation remains a provenance spoof, and the plan's exit criterion ("both distinguishable from a user message") covers only the new verbs. | `packages/realtime-agent/src/transcript.ts:110-112` (`lines()` returns **both** `input` and `output`); `packages/realtime-agent/src/types.ts:9-14` (`AgentTranscriptLine.kind: 'input'|'output'`); `packages/realtime-agent/src/bridge.ts:124-129` (transcript → `DelegationRequest`); `packages/realtime-responder/src/turn.ts:177-180` (`promptFrom` joins **all** lines, kind-blind); `…/commands.ts:331` (`kind:'user'`). | Either filter the question prompt to `input` lines, or attribute the question path with the voice source too. Add a fixture asserting **no text of kind `output` is ever attributed as `user`**. |
| **CHEN-05** | **HIGH** | **The note's "content-only, never directives" boundary and the capability object are conventions, not enforcement — and the flagship exit criterion is untestable.** P3 claims `capabilities:{canStartTurn:false}` is *"checked by the receiver rather than trusted to a prompt."* The receiver that would check it is the DSH agent runtime, which **does not read our field**; the only thing preventing a turn is choosing `inject()` over `followup()`. A future contributor swapping the call would not be stopped — this is exactly the "a file nothing reads is not a contract" failure ADR-008 was written to forbid, inside the plan that cites ADR-008. Separately, the exit criterion *"a planted directive inside a note is **proven not to execute as an instruction** (a test that fails if it does)"* cannot be proven keylessly — it requires a live model and is probabilistic, so it is not a gate. | `docs/sprint-plan-voice-presence.md:207-222` (P3 stories 1/3/4 + exit criteria), `:284-287` (cites ADR-008). `docs/decisions.md:124-146` (ADR-008). The note's delivery path is `agent.inject()` (`packages/core/agent/src/runtime-types.ts:241`), which starts no turn **by construction**, not by reading `capabilities`. | Enforce at the **producer**: make the note payload a **closed shape with no instruction field** (structural; a type + a runtime key check), and assert **the delivery method is `inject()`, not `followup()`** in a unit test (`note-trust.spec.ts`). Restate the injection criterion as *"the note payload carries no directive field and its delivery method cannot start a turn"* — the property *is* enforceable; *model resistance* is not and should not be gated. |
| **CHEN-06** | **HIGH** | **Reachability of the write path from an out-of-tree installed plugin is an unprobed assumption placed in P2, not a P1 gate.** P1 spikes the *wire channel* but never probes whether a `dsh plugin add`-installed package can actually reach `createUserMessage()`, `agent.inject()/followup()`, and `ctx.sessions.flush()`. The spine survey itself flags this as the thing to settle first: *"**Probe that first; it decides the size of everything after it.**"* If unreachable, the plugin's only write path is `prompt()` → user-attributed → and the entire provenance model collapses to CHEN-04. | `docs/session-messaging.md:269-274` (the honest gap); `docs/sprint-plan-voice-presence.md:117-149` (P1 exit criteria — channel only, no reachability cell), `:170-171` (P2 story 4 asserts *"the mechanism is public and documented"*). `dsh-schedule` reaches these **inside the tree** (`runtime.ts:8,269`; `persistence.ts:26`); out-of-tree reachability is what the survey says is unproven. | Add a P1 story: *"prove an out-of-tree plugin can construct a sourced message and deliver it without `sessionController.prompt()`."* Put the answer in `docs/delegation-intent.md` beside the channel result and gate P2 on it. |
| **CHEN-07** | **HIGH** | **No rate/turn cap or loop breaker on the `say` verb, contradicting the research the plan cites.** The plan has idempotency (story 6) but **no bound** on how many turns a voice may start. | **CHEN-08** | **HIGH** | **New journal fields are a new leak sink, and the plan does not say which of them carry text.** The journal deliberately holds **no text today** — outcomes carry sizes and digests only. | **CHEN-09** | **OBSERVATION** | **A note and a say are indistinguishable in the shipped projection, and a turn-starting `say` renders as *context*.** The harness's message projection maps an unknown source kind to `{ role: 'inject', label: kind }` — so both verbs render as an `inject` row. | **CHEN-10** | **OBSERVATION** | **The echo guard's subject is undefined.** P2 story 5 — *"refuses to deliver a voice message back into the session that sent it"* — has no referent: the voice session and the DSH session are different, and the DSH session never sent the delegation. ## What survives

A review that finds only problems is not calibrated. The following are **right**, verified, and should not be weakened in the revision:

- **Provenance-as-a-structural-field is the correct instinct, and the `dsh-schedule` precedent is real and vetted.** `createUserMessage({source})` + `agent.followup()` + `ctx.sessions.flush()` is exactly how an in-tree plugin writes into a session as itself, durably, with a required acknowledgement (`~/dev/deepseek-harness/packages/schedule/schedule/src/runtime.ts:269-273`, `persistence.ts:26`). The plan picked the right model.
- **"Never take attribution from the model" is the correct principle** (research §7, §5.5 rule 1), and it is implementable: the `source` object is built by the producer from constants, and nothing model-supplied flows into it for the two new verbs. F5 is a gap in *coverage*, not a flaw in the principle.
- **Treating the note as the risky verb, marked untrusted, is correct**, and the plan cites the right cautionary tales (Claude Code's unsigned `<system-reminder>` sharing a wire format with untrusted tool output; Anthropic's `tool_result` rule). P3 story 5 is the right lesson.
- **Redaction-on-write is structural, not per-field.** `Journal.record` redacts every value before it is retained (`journal.ts:242-246`), so a new journal field is redacted **by construction** — the plan's instinct that "sentinel tests extend, not shrink" is well-founded. The remaining work is to say *which* fields carry text (CHEN-08), not to rebuild the mechanism.
- **Producer-minted message ids for idempotent consumption** is the correct pattern (research §3.2) and the plan states it correctly.
- **Fail-closed classification *is* testable** as a pure function over `(delegation, transcript)` with fixtures. The plan is right that it is machine-verifiable. The defect is in the *name* (CHEN-01), not the testability.
- **Refusing to mint a metadata file nothing reads** (ADR-008 discipline, `sprint-plan-voice-presence.md:284-287`) is the right instinct and is applied consistently — with the single exception of the `capabilities` field it introduces (CHEN-05).

## Could not verify

- **Whether the plan's `delegation-intent.spec.ts` classification is achievable at all.** The wire vocabulary carrying no intent is taken as given (established fact); I did not re-derive it. What I could **not** check is whether instruction-based classification can be made unambiguous enough for the four P1 fixtures to be meaningful — that needs the live spike the plan proposes, which I cannot run.
- **Whether the harness's tool-approval gate** (the backstop CHEN-02 says is missing from the plan) is actually active for a configured session, and whether it fires on a `say`-started turn. The harness is out of scope of this repo (`SECURITY.md` "Out of scope: the DeepSeek Harness itself"), and I found no approval-policy configuration in the profile or `cordis.patch.yml`. The plan should establish this itself; I flag it as the missing piece, not as a proven bypass.
- **`research/session-messaging-protocols.md` §6 and the vendor claims in §4** are read at the summary level only; the plan's *market* claims (S1–S4 provenance signals, Zendesk/Teams specifics) are not security-load-bearing and I did not re-source them.
- **The `docs/protocol.md` "rejects unknown fields" claim** and the absence of a tool-call vocabulary were taken as given; I did not exercise the live endpoint.
